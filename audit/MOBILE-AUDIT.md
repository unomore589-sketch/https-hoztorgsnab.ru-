## План

1. **Убрать препятствия** — находки 1–3, 5, 7, 8, 10–13.
2. **Мобильная навигация** — нижняя панель (каталог, поиск, корзина, кабинет, звонок) и
   шапка в одну строку; поиск на весь экран с фото и ценой; вид «списком» с − / +;
   закреплённая кнопка «В корзину» и шкала до 3 000 / 35 000 ₽; «Повторить заказ».
3. **Технологии** — Speculation Rules, WebP + lazy-loading, PWA, голосовой поиск,
   заказ по списку артикулов, подбор по описанию задачи.

Первый шаг: количество в корзине и кнопка «Фильтры». Нужны шаблон корзины и шаблон раздела каталога.

## Повторный замер

```
node audit/scripts/audit.js <папка для скриншотов>   # цифры по 7 страницам → metrics.json
node audit/scripts/flow.js  <папка для скриншотов>   # сценарий покупки → flow.json
```

Скрипты ждут Playwright в `/opt/node-tools/node_modules/playwright` и Chromium в
`/opt/pw-browsers/chromium`; `flow.js` кладёт один товар в корзину гостевой сессии.

Причины: `@media (max-width:480px) .stepper{display:none!important}` и
`@media (max-width:480px) .sidebar_right{display:none}` в общем файле стилей.

Проверка (`scripts/verify-cart-filters.js`): новый CSS и JS подставлялись в живые страницы
только в браузере, на сайте ничего не сохранялось.
- Фильтры: 16 товаров → отметка «120 л.» → 4 товара, кнопка «Показать 4 товара» → «Сбросить» → 16.
- Корзина: три нажатия «+» ушли одним запросом `cart/change` с `count=4`; «−» → 3; ввод 30 → сумма 1008;
  ниже 1 кнопка «−» не опускает; подсказка о минимальном заказе пересчитывается.

Не проверено: вывод через Fenom на сервере (шаблон корзины рендерит miniShop2) и настоящие телефоны.

Замечено по пути, не исправлялось:
- `position: sticky` в каталоге не работает из-за `#wrapper2 { overflow: hidden }`.
- Обработчик `button.addtocart` в общем скрипте (`scripts_*.min.js`, строка 693, колонка 111) падает в списках
  товаров на `Main.find('h1.page_heading').html().trim()`: в шаблоне «Подкатегория» заголовок h1 стоит вне
  `#main` (`#main h1.page_heading` не находится), `.html()` возвращает undefined. Событие «добавление в
  корзину» для электронной коммерции Метрики из списков не уходит; товар в корзину попадает.
  (Первая версия этой заметки называла причиной отсутствие поля количества — это было неверно.)
- После изменения количества miniShop2 перерисовывает корзину, и в строке пропадает артикул («Код:» пустой).
