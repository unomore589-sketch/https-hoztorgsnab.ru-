## 1. Задача

В личном кабинете `hoztorgsnab.ru/profil.html` (ресурс MODX id **81**, псевдоним `profil`,
шаблон **«Профиль»**) вкладка «История заказов» на телефоне нечитаема: колонки таблицы
обрезаются до 1–2 символов. Нужен мобильный вид с удобными функциями для заказа.

**Статус:** код написан и лежит в репозитории. **В MODX он, возможно, ещё не вставлен и в
браузере ни разу не запускался** — см. раздел 4.

## 2. Как устроен личный кабинет (результат разведки — чтобы не копать заново)

Цепочка вывода истории заказов:

```
Шаблон «Профиль»
  └─ <div class="tab-pane active" id="zakaz">[[!officeMiniShop2?]]</div>
       └─ сниппет officeMiniShop2  (обёртка в 8 строк)
            └─ сниппет Office, action = 'miniShop2'   ← пакет MODX Office
                 └─ отдаёт в HTML только пустой <div id="office-minishop2-grid">
                      └─ таблицу дорисовывает JS на ExtJS 3.x после загрузки страницы
```

Ключевые выводы разведки:

- **Таблицы заказов нет в HTML.** Исходный код страницы содержит только пустой контейнер
  `#office-minishop2-grid` и прелоадер. Всё рисует ExtJS (`/assets/components/office/cache/main/*.js`).
- **Чанка-шаблона строки заказа не существует.** Проверены `tpl.msOrd` и `tpl.msGetOrder` из
  папки чанков `miniShop2` — оба оказались про оформление заказа («Спасибо за заказ» + скрытая
  таблица корзины), к истории заказов отношения не имеют. Чанки `tpl.Office.*` — только про
  авторизацию. Колонки грида задаются конфигом в JS:
  `OfficeExt.config.order_grid_fields = ["num","status","cost","weigh","delivery","payment","createdon","updatedon","id","type","actions"]`.
- **ExtJS 3.x чинить бессмысленно**: библиотека без поддержки с ~2012 года, ширины колонок
  считает в пикселях под десктоп, шапка и тело — разные DOM-контейнеры со синхронным скроллом.
  CSS-переливание строк в карточки для неё ненадёжно.
- **Поэтому выбран обход**: свой лёгкий список обращается к тому же серверному API, что и грид,
  и рисует карточки. Грид не трогаем — на десктопе всё работает как раньше.
- Другие вкладки: «Профиль» — `[[!officeProfile?&HybridAuth=`0`&tplProfile=`tpl.Office.profile.form2`]]`,
  «Сохранённые корзины» — `[[!msBasketsList?]]`. **Они не трогались.**

## 3. Справочник API (снято с реальных запросов через DevTools → Network)

Общий адрес: `POST https://hoztorgsnab.ru/assets/components/office/action.php`
Формат тела: `application/x-www-form-urlencoded`. Авторизация — по сессионной куке
(запрос с того же домена, `credentials: 'same-origin'`).

**Список заказов** (проверено полностью — запрос и ответ):

```
action=minishop2/getOrders&start=0&limit=20&pageId=81
```

```json
{"success":true,"total":1,"results":[{
  "num":"1806/25",
  "status":"<span style=\"color:#000000;\">Новый</span>",
  "cost":"73000",
  "delivery":"Самовывоз",
  "payment":"",
  "createdon":"2018-06-11 14:30:21",
  "updatedon":"",
  "id":"1583",
  "type":"0",
  "actions":[{"icon":"fa fa-info-circle","title":"Подробность","action":"viewOrder","button":true,"menu":false}]
}]}
```

**Состав заказа** (запрос проверен, ответ прочитан не до конца — см. раздел 6):

```
action=minishop2/getOrderProducts&start=0&limit=5&order_id=1583&pageId=81
```

Поля позиции — по конфигу `OfficeExt.config.order_product_fields`:
`["name","product_article","weight","price","count","cost","product_id","url"]`.
Колонки в интерфейсе подтверждают: Товар, Артикул, Вес, Цена, Количество, Стоимость.

**Важно:** у заказа в `actions` есть **только** `viewOrder`. Действия «повторить заказ» на
сервере не существует — его придётся собирать на стороне клиента через корзину miniShop2.

## 4. Что сделано и где лежит

| Файл в репозитории | Куда вставлять в MODX |
|---|---|
| `modx-chunks/lichny-kabinet-mobile.html` | Элементы → Чанки → чанк **LichnyKabinetMobile** (id 207) → поле «Код чанка (HTML)» |
| `modx-templates/profil.html` | Личный кабинет (81) → Настройки → Шаблон → «Открыть» → поле «Код шаблона (HTML)» |
| `README.md` | никуда, описание задачи |
| `HANDOFF.md` | этот файл |

Что делает код чанка:

- сам запрашивает заказы у `action.php` и рисует карточки: номер, дата, статус-бейдж, сумма,
  способ доставки, кнопка «Показать состав заказа» (состав догружается по клику, один раз, потом
  кэшируется в DOM);
- кнопка «Обновить» перезагружает список без перезагрузки страницы;
- переключение видов чистым CSS: ширина **> 768px** — виден штатный ExtJS-грид, мобильный блок
  скрыт; **≤ 768px** — грид `#office-minishop2-grid` скрыт, видны карточки.

В шаблоне относительно оригинала изменена **одна строка** — добавлен `[[$LichnyKabinetMobile]]`
сразу после `[[!officeMiniShop2?]]` внутри `<div ... id="zakaz">`. Больше ничего не менялось.

## 5. Что НЕ проверено (важно для того, кто продолжит)

- **Код ни разу не выполнялся в браузере.** Написан по снятым запросам, но живой проверки не было.
- **Неизвестно, вставлен ли он в MODX.** Чанк `LichnyKabinetMobile` (207) создан пользователем
  ранее — но с первой, демонстрационной версией кода (выдуманные заказы). Рабочая версия из
  `modx-chunks/lichny-kabinet-mobile.html` могла быть ещё не сохранена поверх. Правка шаблона
  «Профиль» тоже не подтверждена.
- **Ответ `getOrderProducts` прочитан только с начала** (`{"success":true,"total":1,"results":[{"name":…`).
  Имена полей взяты из конфига. Если в блоке состава пусто или значения не те — проверять в первую
  очередь здесь: снять полный Response этого запроса и сверить с тем, что читает код
  (`p.name`, `p.count`, `p.price`, `p.url`).

**Порядок проверки:**

1. Вставить оба файла в MODX (таблица в разделе 4), сохранить. Галка «Очистить кэш при сохранении»
   должна быть включена.
2. Открыть `hoztorgsnab.ru/profil.html`, войти клиентом.
3. DevTools → иконка телефона (Ctrl+Shift+M) → выбрать любой телефон.
4. Ожидается: вкладка «История заказов» показывает карточку заказа №1806/25 — «Новый», 73 000 ₽,
   Самовывоз, 11.06.2018. По кнопке «Показать состав заказа» — «Скамейка (ТН) 1500x710… 10 × 7 300 ₽».
5. Выключить режим телефона → должна вернуться обычная таблица ExtJS.
6. Если пусто или ошибка — смотреть вкладку Console на предмет ошибок JS и вкладку Network:
   ушёл ли POST на `action.php` и что он вернул.

## 6. Что осталось сделать

### 6.1. Кнопка «Повторить заказ» (главная недостающая функция)

Ради неё всё и затевалось — для оптовика повтор прошлой закупки в один клик ценнее всего
остального. Серверного метода нет, собирается на клиенте:

1. Снять запрос добавления в корзину: открыть любой товар на сайте, DevTools → Network →
   фильтр Fetch/XHR, нажать «В корзину», найти запрос к `/assets/components/minishop2/action.php`,
   записать **Payload** (там будет что-то вида `action=cart/add&id=…&count=…`) и **Response**.
2. Убедиться, что `getOrderProducts` реально отдаёт `product_id` для каждой позиции (заявлен в
   конфиге, фактически не проверен).
3. Дописать в чанк кнопку: по клику — цикл по позициям заказа, для каждой вызов добавления в
   корзину с её `product_id` и `count`, затем переход на `/cart.html`.
4. Предусмотреть: товар мог быть снят с продажи или подорожать — показывать, что именно не
   добавилось, а не молча терять позиции.

### 6.2. Прочее, по убыванию пользы

- **Пагинация.** Сейчас в мобильном списке жёстко `limit=20` и кнопок страниц нет. У тестового
  клиента 1 заказ, но у активного оптовика заказов больше — нужна подгрузка «Показать ещё».
- **Остальные две вкладки на мобильном.** Правились только заказы. Вкладки «Профиль» и «Список
  сохранённых корзин» на телефоне не проверялись — в корзинах используется обычная `<table>`
  с 4 колонками, она, скорее всего, тоже узкая.
- **Вес страницы.** ExtJS грузится на мобильном по-прежнему (грид просто скрыт через CSS) —
  это 5+ JS-файлов впустую. Если понадобится ускорение мобильной загрузки, это отдельная задача:
  не выводить `[[!officeMiniShop2?]]` при мобильном User-Agent.

## 7. Подводные камни

- **`pageId=81` зашит в JS чанка.** Если страницу личного кабинета пересоздадут с другим id —
  запросы начнут возвращать пустоту. Это же значение фигурирует в `OfficeConfig.pageId` на странице.
- **Статус приходит HTML-строкой** с инлайновым цветом (`<span style="color:#000000;">Новый</span>`).
  Код берёт из неё только текст и красит бейдж сам, по ключевым словам: «нов» → синий,
  «выполн»/«заверш» → зелёный, «отмен» → красный, «обработ»/«сбор»/«пути» → жёлтый, остальное —
  серый. Новый статус в админке получит серый бейдж — это не поломка, а поведение по умолчанию;
  добавлять новые слова в функцию `htsMoStatusClass`.
- **`updatedon` у заказов бывает пустым** — в карточке не выводится.
- **Fenom в этом проекте всё-таки встречается**, вопреки общему правилу «только нативные теги
  MODX»: чанки самого miniShop2 (`tpl.msOrd`, `tpl.msGetOrder`) написаны на Fenom (`{foreach}`,
  `{if}`), потому что miniShop2 парсит их своим шаблонизатором. На обычные страницы сайта это
  не распространяется — там по-прежнему `[[*field]]` / `[[$chunk]]`.
- **TinyMCE.** Код кабинета живёт в чанке и шаблоне, а не в поле «Содержимое» ресурса —
  именно поэтому он не ломается редактором. Не переносить его в контент ресурса.
- **Классы.** Все свои классы с префиксом `hts-`, критичные свойства продублированы `!important` —
  глобальный CSS шаблона переопределяет голые теги.
